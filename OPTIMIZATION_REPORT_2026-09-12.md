# Kapani — точечная оптимизация 2026-09-12

## Изменённый файл
- `index.html`

Остальные файлы проекта оставлены без изменений.

## Что исправлено

### Главная статистика
- `renderHomeStats_users()` теперь реально используется через общий кэш пользователей.
- Баланс главной синхронизируется с `attachUserListener()`/`updateHeader_balance()` без отдельного Firebase-чтения.
- При входе на Home кэш `/users` загружается максимум один раз за текущую сессию клиента и далее переиспользуется.
- «Заказов» считается по существующему понятию активного заказа: taxi-статусы из `TAXI_ACTIVE_STATUSES`, для прочих заказов `waiting/in_progress`.
- Рендер статистики защищён от отсутствующего DOM-узла.

### Чат и DM
- Открытие DM сначала берёт пользователя из `allUsersCache`, а не делает обязательный `get(users/<nick>)`.
- В `renderDmMessages()` убрано отдельное чтение текущего пользователя из Firebase.
- Закрепление DM и переключение вкладки больше не скачивают весь `/users`, когда кэш уже есть.
- Общий чат больше не вычисляет список всех пользователей заново для каждого сообщения.
- Существующие realtime listeners и generation-защита DM сохранены.
- Дублирующий полный ререндер/сетевой путь не добавлялся.

### Казино
- `casinoRound()` теперь использует `tx.snapshot.val()` после транзакции вместо повторного `get(user)`.
- Slots/Roulette/Coin Flip/Dice используют свежий объект пользователя из кэша после операции.
- Blackjack и Slots также обновляют UI из результата транзакции.
- История/поступления в казну вынесены из критического UI-пути и не удерживают игровую кнопку только из-за медленного вторичного запроса.
- При открытии казино основной пользовательский объект читается один раз; пять игровых блоков получают этот объект.
- Правила ставок, коэффициенты, транзакции, operation ID/защита от повторов и баланс не изменялись.

### Рамки
- Добавлена единая карта `AVATAR_FRAME_CLASSES` и `getAvatarFrameClass()`.
- Проверка активной подписки теперь единообразна.
- Единая система применяется к собственному профилю, профилю пользователя, полной странице чужого профиля, DM, общему чату, списку DM, маркету и рейтингу.
- На полной странице чужого профиля добавлен отдельный `vpfAvatarFrame`.
- Видео-аватары не заменены и продолжают использовать существующую систему media toggle.

### Фоны профиля
- Добавлена единая карта `PROFILE_BG_CLASSES` и `getProfileBgClass()`.
- Старые классы всегда очищаются перед установкой нового.
- Полная страница чужого профиля и модальное окно чужого профиля больше не оставляют эффект предыдущего пользователя.
- Существующие эффекты и условия активной подписки сохранены.

## Ограничение
Полноценный браузерный runtime-тест с реальным Firebase в этой изолированной среде не выполнен: запуск Chromium против локального HTTP-ресурса был заблокирован средой (`ERR_BLOCKED_BY_ADMINISTRATOR`). Поэтому фактическое поведение Firebase/realtime в продакшн-окружении не выдаётся за проверенное.
