# Kapani — push fix (2026-09-10)

## Что изменено

- `index.html` больше не использует Cloudflare Push Bridge для `/register`, `/push`, `/diagnostics`.
- FCM token регистрируется через Firebase callable Function `registerFcmToken`.
- Push preferences синхронизируются через `updatePushPreferences`.
- Выход удаляет token через `unregisterFcmToken`.
- Диагностика использует `getPushDiagnostics`.
- `pushNotification()` только создаёт canonical RTDB notification. Доставка выполняется backend-триггером `enqueueNotificationPush` + `notificationQueue` + `processNotificationQueue`, поэтому клиентский JS не нужен в момент доставки.
- При проблемах Firebase Auth фронтенд теперь показывает предупреждение и повторяет создание custom-token с backoff; при следующем push-действии выполняется попытка восстановить защищённую Firebase-сессию без обязательного ручного релогина, пока пароль доступен в памяти текущей сессии страницы.
- В UI push-настроек добавлен видимый диагностический статус.
- `config.js` больше не содержит `pushBridgeUrl`.
- `cloudflare-worker/` явно обозначен как legacy-архив; Worker не входит в активный push path.
- `cloudflare-worker/wrangler.toml` содержит Firebase Web API key, побайтово совпадающий с `config.js`.

## Важное ограничение слова «гарантированно»

Система сделана server-authoritative с очередью и retry. Она не зависит от открытой вкладки получателя: backend хранит job и повторяет отправку FCM. Фактическая работа Web Push зависит от поддерживаемого браузера/ОС, разрешения Notifications, активной регистрации Service Worker и самого FCM/Web Push транспорта.

## Production checklist

1. `firebase deploy --only functions` — должны быть задеплоены как минимум `registerFcmToken`, `unregisterFcmToken`, `updatePushPreferences`, `getPushDiagnostics`, `enqueueNotificationPush`, `processNotificationQueue` и остальные существующие Functions.
2. Проверить, что Firebase Authentication API доступен и custom-token sign-in реально работает в production.
3. Перепроверить RTDB rules: `notificationQueue` и `fcmTokenIndex` изменяются через Admin SDK Functions и не должны требовать клиентской записи.
4. На GitHub Pages проверить фактические URL: `/kapani/index.html`, `/kapani/config.js`, `/kapani/firebase-messaging-sw.js`. Service Worker должен регистрироваться в scope `/kapani/`.
5. После деплоя в браузере выполнить `await window.getKapaniPushDiagnostics()` и добиться: `permission === "granted"`, `fcmTokenExists === true`, `serverRegistered === true`, `serverTokenCount >= 1`.
6. Финальный E2E-тест: полностью закрыть вкладки Kapani у получателя, отправить событие с другого аккаунта, убедиться, что соответствующий `notificationQueue/{jobId}` приходит в `sent`, а системное уведомление появляется через `firebase-messaging-sw.js`.
7. Для iPhone тестировать установленный Home Screen/PWA-сценарий с разрешёнными уведомлениями.
